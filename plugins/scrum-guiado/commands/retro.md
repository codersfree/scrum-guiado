# Retro

Explica, la primera vez, qué es la retrospectiva (mirar **cómo** se trabajó para mejorar, no qué se construyó). Con **`scrum-master`**, **una pregunta a la vez**:
1. ¿Qué funcionó bien? 2. ¿Qué te frenó o confundió? 3. ¿Qué cambiarías el próximo sprint?
Complementa con datos: tareas terminadas frente a planificadas, bloqueos, tareas que se pausaron (de las bitácoras).
Propón **máximo 3 acciones** concretas con responsable y fecha, y pide aprobación. Si una acción cambia un acuerdo (DoD, DoR, ritmo), actualiza el documento en `docs/scrum/`; si es sobre este paquete, anótalo para ajustarlo.
Guarda `docs/scrum/sprints/<sprint>/retro.md`. Cierra el sprint: pregunta si se planifica el siguiente (`/scrum-guiado:sprint` repite el planning para el sprint-02 con el backlog actualizado; crea la carpeta `sprint-02` y actualiza "Sprint actual").
